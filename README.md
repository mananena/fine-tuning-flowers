# Fine-Tuning: классификация цветов

Проект для лабораторной: сравнение ResNet18 и MobileNetV3 Small, подбор скорости
обучения, оценка ошибок, экспорт выбранной модели в ONNX и локальное приложение.

**Текущий статус:** четыре эксперимента выполнены, тестовые метрики рассчитаны,
лучшая модель экспортирована в ONNX и проверена на test. Данные открытые;
требование самостоятельной съёмки не выполнено.

## Структура

```text
experiments/
  data/raw/                 # свои фотографии по папкам классов
  data/README.md            # описание сбора
  notebooks/experiments.ipynb
  train.py                  # dataclass, обучение, выбор и экспорт
  preprocessing.py          # общая предобработка
  runs/                     # split, конфигурации, логи и графики
  models/                   # выбранная модель ONNX и метаданные
app/
  app.py                    # Gradio + ONNX Runtime CPU
  requirements.txt          # лёгкое окружение приложения
requirements.txt
```

## Установка (Windows, Python 3.11)

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
jupyter lab
```

Первый запуск обучения скачивает предобученные веса и требует интернет.
Зависимости зафиксированы по версиям; эксперименты выполнены в среде, описанной в логах запусков.
Для CPU подходят модели малого размера; базовый размер входа 160 вместо 224
уменьшает вычисления и может снизить качество. Для CUDA установите совместимую
с драйвером сборку PyTorch. Все команды запускайте из корня проекта.

## Данные и эксперименты

1. В `experiments/data/raw/` уже включены 180 открытых фотографий.
   Происхождение, отбор и ограничения описаны в `experiments/data/README.md`.
2. Откройте ноутбук и выполните ячейки по порядку. Он запускает четыре эксперимента:
   две архитектуры × две скорости обучения, одинаковый seed и общий сплит.
3. Две первые эпохи обучается только классификатор. Затем размораживается вся
   модель с меньшей скоростью для backbone. AdamW, weight decay и cosine scheduler
   задаются в коде; параметры сгруппированы в `TrainConfig`.
4. Выбор лучших гиперпараметров выполняется по validation accuracy. При равенстве
   используется первый запуск в алфавитном порядке. После выбора тестируются
   лучшие варианты каждого семейства и экспортируется общий победитель.
5. Изучите кривые, матрицы ошибок и неверно классифицированные фотографии.
   Допишите в ноутбуке собственную интерпретацию фактических результатов.

Один запуск вручную:

```powershell
python -m experiments.train --model resnet18.a1_in1k --run-name resnet_lr001 --lr 0.001
python -m experiments.train --model mobilenetv3_small_100.lamb_in1k --run-name mobile_lr001 --lr 0.001
python -m experiments.train --finalize
python -m app.app
```

Сервер Gradio запускается локально, ссылка выводится в терминале. Дополнительное
окружение приложения можно установить из `app/requirements.txt`; PyTorch ему
не нужен. Функция предобработки общая с оценкой модели. Экспорт проверяется
ONNX checker и сравнением logits/классов PyTorch и ONNX на тестовых изображениях.
Размер входа ONNX фиксирован: один снимок, три канала, размер из метаданных.

## Воспроизводимость и результаты

Фиксируются Python random, NumPy, PyTorch, CUDA и DataLoader. Включены
детерминированные операции; между разными устройствами идентичные числа
не гарантируются. Сохраняются конфигурация, версии PyTorch/timm, split с хешами,
история каждой эпохи, лучший checkpoint и длительность обучения.

Не запускайте повторный подбор после просмотра test accuracy: иначе test
перестанет быть независимой оценкой. Для нового набора используйте другую папку
`--runs`; при изменении данных сохранённый split отклоняется.

Для сдачи необходимо согласовать использование открытого набора вместо собственной съёмки.
Результаты и выполненный notebook включены в репозиторий.
Большие .pt/.onnx лучше разместить в GitHub Release или Git LFS и указать ссылки.
Подвыборка фотографий включена в проект вместе с исходными лицензиями. Ссылку на репозиторий прикрепите в LMS.

## Результаты выполненных экспериментов

| Запуск | lr | Validation accuracy | Test accuracy | Время, с | Параметры |
|---|---:|---:|---:|---:|---:|
| mobile_lr0.0003 | 0.0003 | 0.778 | не оценивалась | 8.4 | 1,520,931 |
| mobile_lr0.001 | 0.001 | 0.926 | 0.741 | 8.2 | 1,520,931 |
| resnet_lr0.0003 | 0.0003 | 0.333 | не оценивалась | 18.3 | 11,178,051 |
| resnet_lr0.001 | 0.001 | 0.815 | 0.852 | 19.3 | 11,178,051 |

По validation выбрана модель **mobilenetv3_small_100.lamb_in1k**, запуск `mobile_lr0.001`. Её test accuracy составила **0.741** на 27 снимках.

Набор небольшой: одна ошибка на test меняет accuracy примерно на 3.7 процентного пункта. Поэтому различие в одну фотографию не даёт надёжного доказательства превосходства архитектуры.

Для `mobile_lr0.001` самая частая путаница: sunflowers → roses, 2 снимков. Примеры ошибок показаны в ноутбуке.
К последней эпохе train loss уменьшилась, а validation loss выше достигнутого минимума. Это повод остановиться на сохранённом checkpoint; по короткой кривой нельзя уверенно установить причину роста.
Для `resnet_lr0.001` самая частая путаница: sunflowers → daisy, 2 снимков. Примеры ошибок показаны в ноутбуке.

Время измерено на одной машине и включает обучение и validation, но не скачивание весов. Число параметров описывает размер модели, а не напрямую её задержку в приложении.

Ограничения: открытые фотографии вместо самостоятельной съёмки, один seed, небольшой test, возможные похожие изображения, отсутствие проверки на другом устройстве. Для улучшения оценки нужны собственные новые снимки и несколько повторов разбиения.



### Почему для приложения выбрана MobileNetV3

При выборе ориентировался на validation, а не на test: 25 правильных ответов
из 27 у MobileNetV3 против 22 из 27 у ResNet18. Дополнительно MobileNetV3
содержит примерно в 7.3 раза меньше параметров и обучилась за 8.2 с против
19.3 с у ResNet18 на том же CPU. Для небольшого локального приложения это
полезный компромисс. Размер ONNX MobileNetV3 около 6 МБ; пример инференса
в проверке приложения занял 2.4 мс. Одно измерение задержки не является
полноценным бенчмарком и не включает декодирование файла.

На test порядок моделей оказался обратным: ResNet18 правильно распознала
23 из 27 снимков (85.2%), MobileNetV3 — 20 из 27 (74.1%). Это расхождение
сохранил в результатах. Оно показывает, что выбор по маленькой validation
выборке нестабилен. Менять победителя на основании test после подбора нельзя:
для следующего исследования нужны новая независимая выборка или несколько
разбиений. Результаты относятся к этим гиперпараметрам и шести эпохам,
а не доказывают преимущество одного семейства моделей в целом.

### Что видно на кривых и ошибочных снимках

У MobileNetV3 при lr=0.001 в первых двух эпохах train loss остаётся выше 5.
После размораживания на третьей эпохе она снижается до 3.59, а к четвёртой —
до 0.75. В этом запуске обучение одного классификатора оказалось недостаточным;
настройка признаков заметно помогла. При lr=0.0003 за тот же бюджет модели
обучились хуже. Особенно это видно у ResNet18: validation accuracy лишь 33.3%.
Более низкий lr здесь не означает более качественную модель; возможно,
ему требуется больше эпох, но это отдельно не проверялось.

В двух ошибках daisy → sunflowers крупная жёлтая сердцевина и радиальные
лепестки визуально напоминают подсолнух. На снимках подсолнухов встречаются
букет на фоне человека и общий план поля: объект занимает другую долю кадра,
чем крупные цветы. Center crop также может убирать полезный контекст.
Это возможные объяснения, а не доказанное устройство признаков модели.

На `roses/3713368809_eba7fa2fbf_m.jpg` изображена группа людей и видимого
цветка нет. Это явная проблема исходной разметки выбранного набора. Снимок
обнаружен при разборе test; я не удалял его после оценки, чтобы не улучшать
метрику задним числом. Перед новым экспериментом стоит проверить весь набор,
зафиксировать исправления и заново разделить данные. Текущие числа сохранены
вместе с этим ограничением.

Экспорт проверен на всех 27 тестовых снимках: классы PyTorch и ONNX совпали,
максимальное абсолютное расхождение logits — 0.0000677. Интерфейс Gradio
создан успешно, его функция классификации возвращает три вероятности,
сумма которых равна единице. Это проверка построения интерфейса и инференса;
ручное взаимодействие с сервером на пользовательском ПК ещё не проверялось.


## Повторное обучение и сохранённые веса

В репозитории опубликованы результаты и готовая ONNX-модель. Checkpoint .pt
сохранены в артефакте `laboratory-results` успешного запуска GitHub Actions:
https://github.com/mananena/fine-tuning-flowers/actions/runs/38170375608
Скачайте артефакт и восстановите файлы в experiments/runs, если хотите
повторно выполнить экспорт сохранённых моделей. Для запуска Gradio .pt не нужны.

Чтобы заново обучить модели, используйте новую папку результатов:

```powershell
python -m experiments.train --runs experiments/runs_repeat --model resnet18.a1_in1k --run-name resnet_lr001 --lr 0.001
python -m experiments.train --runs experiments/runs_repeat --model resnet18.a1_in1k --run-name resnet_lr0003 --lr 0.0003 --backbone-lr 0.00003
python -m experiments.train --runs experiments/runs_repeat --model mobilenetv3_small_100.lamb_in1k --run-name mobile_lr001 --lr 0.001
python -m experiments.train --runs experiments/runs_repeat --model mobilenetv3_small_100.lamb_in1k --run-name mobile_lr0003 --lr 0.0003 --backbone-lr 0.00003
python -m experiments.train --runs experiments/runs_repeat --finalize
```

Опубликованный notebook уже выполнен. Для повторного выполнения без скачивания
checkpoint сначала сохраните копию notebook и замените пути `experiments/runs`
на `experiments/runs_repeat`; к командам обучения и `--finalize` добавьте
`--runs experiments/runs_repeat`. Чтение опубликованных графиков не требует
повторного обучения. В старых config.json пути отражают машину первоначального
запуска; новые запуски фиксируют пути вашей машины.
